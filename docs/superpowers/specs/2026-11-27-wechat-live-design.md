# 微信 Live · 设计规格

> 目标：在「PC微信」插件里新增一块名为 **微信 Live** 的界面，复刻
> `C:/myself/projects/my/open-source/wechat-assistant`（WeFlow）除「首页」「灵感信箱」以外的
> 全部菜单与功能，AI 部分改用 DSH 客户端自己的 AI。
>
> 状态：**草稿，待用户审阅**。
> 来源取舍：凡 WeFlow 已有、侧车能支撑的，**照它的逻辑做**，不另立口径。

---

## 1. 背景与边界

### 1.1 现状

`plugins/vyra-wechat-local` 目前只有两块：

- **Host**（`index.js`）：启动 Python 侧车、注册 18 个工具、一条 RPC 路由、一条头像路由；
- **设置页**（`client.js`）：一个「PC微信」入口，内含 回复策略 / 画像蒸馏 / 状态信息 三个页签。

侧车（`vendor/wechat/`）是 lumii 的产品，能力集中在**聊天读取与发送**，没有联系人全量、
朋友圈、媒体索引、统计聚合。

### 1.2 目标

1. 左侧栏新增一行 **微信 Live**；点开后是一个多页面板。
2. 面板内**顶部横向菜单 6 项**（看微信）+ **底部横向菜单 5 项**（算数据、产出文件）。
3. 11 个页面：用户画像、聊天、AI Agent、朋友圈、通讯录、资源浏览、聊天分析、年度报告、
   我的足迹、导出、数据库备份。
4. AI 相关能力（AI Agent、画像生成、群聊总结）**一律走 DSH 会话**，不自己接模型。
5. 现有的「PC微信」设置页**精简为控制器**：保留与 Live 页面的开关，以及 Live 初始化引导所需的最少项。

### 1.3 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 修改本地消息 | 写微信数据库，高危，与本插件「只读」定位冲突 |
| 防撤回 | 需要常驻进程拦截，DSH 插件生命周期不保证 |
| HTTP API 服务（WeFlow 的 5031） | DSH 自身就是服务，重复 |
| 应用锁 | DSH 宿主已有权限体系 |
| 关系成就 / 关系旅程（`RelationshipAchievementsPage`、`journey`） | 依赖 WeFlow 自己的成就规则库，与「看微信」无关 |
| 工作台 / 个人版双模式 | WeFlow 仓库里是**规划文档**，不是现有功能 |
| 模型多配置管理 | 用 DSH 已配置的模型，不重复造 |
| 导出自动化（定时导出） | 独立调度器，价值低、夜间扫库风险高 |
| 「首页」与「灵感信箱」 | 用户明确不要 |

## 2. 导航与外壳

### 2.1 宿主挂载点

登记三个座位，不接管任何宿主既有 UI：

| 座位 | 登记内容 |
|---|---|
| `sidebar.panellist` | `{ id: 'wechat-live', order: 70, label: () => '微信 Live' }`，图标沿用现有微信气泡（`currentColor`、16×16 矢量、1px 描边） |
| `main` | `{ key: 'wechat-live' }` → `LiveApp`（主面板） |
| `shell.overlay` | `{ id: 'wechat-live-theater' }` → `LiveTheater`（**仅在需要整屏时挂载**：年度报告全屏、大图预览、媒体播放）。平时渲染 `null` |

点击侧栏行 → `ctx.layout.selectPanel('wechat-live')`。

三个座位互相独立登记、独立销毁：任一座位被移除，其余仍可用（`main` 消失则整块不可见，
`shell.overlay` 消失则降级为面板内滚动，不报错）。

**不碰**：`root`、`sidebar`、`main.conversation`，也不修改 `shell.overlay` 上的既有登记。

### 2.2 面板布局

```
┌────────────────────────────────────────────────────────────┐
│ ┌─────────────────────────────────────────────────┐ 账号▾ ⚙ │
│ │ 用户画像 聊天 AI Agent 朋友圈 通讯录 资源浏览   │         │
│ └─────────────────────────────────────────────────┘         │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                      当前页面                               │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ ┌────────────────────────────────────────────────────────┐ │
│ │ 聊天分析 年度报告 我的足迹 导出 数据库备份      状态 ●  │ │
│ └────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- 顶部与底部各是一个横向胶囊导航（结构参照 `vyra-media-desk` 的顶栏：胶囊底、选中态实心）。
- 右上角 `账号▾`：多账号切换（等价 WeFlow 的「账号管理」），`⚙`：打开「PC微信」设置。
- 右下角 `状态 ●`：侧车连接状态灯（绿=已连接 / 黄=降级 / 红=未连接），悬停显示原因，
  点击打开「状态信息」。
- 容器与控件**只用 DSH 主题令牌**（`--dsw-alias-*`、`--dsw-elevation-*`、`--dsw-radius-*`），
  跟随亮/暗主题。不复刻 WeFlow 的玻璃拟态、彩色光斑、Liquid Glass。

### 2.3 路由与状态

- 路由存在 `~/.dsh/wechat-local/live-ui.json`：`{ page, subState }`，刷新后回到上次页面。
- 页面切换时用 `ctx.layout.beginNavigation()` 的中断信号取消在途请求。
- 页面级状态（筛选条件、滚动位置）留在内存，退出面板即丢弃——只有「上次看的是哪一页」落盘。

### 2.4 侧栏开关

「PC微信」设置页提供 `sidebar: boolean`。关闭后侧栏不再出现「微信 Live」行，
但 `main` 面板仍保留（可从命令或设置页跳转打开）。

## 3. 数据层

### 3.1 三层结构

```
页面 (client.js)
   ↓  fetch  /wechat-live.rpc
Host 门面 (lib/live/data.js)
   ↓  JSONL
侧车 vyra_sidecar + vyra_live.py
   ↓  只读
微信 4.x 本地数据库（SQLCipher）
```

页面**不直接调侧车工具**，全部经 Host 门面。门面负责：账号切换、缓存、并发去重、
把侧车的错误信封原样上抛（**不包装成空结果**，见 DESIGN.md §4）。

### 3.2 侧车增补：`vendor/wechat/vyra_live.py`

沿用 `vyra_sidecar.py` 的包装模式：import 未改动的 `sidecar.py` 与 `wechat_core`，
只往 `DISPATCH` 追加工具。**上游文件一行不改**，便于整目录替换 lumii。

新增 7 个工具，**全部不进 Agent 白名单**（`lib/tools.js` 不变），仅供页面：

| 工具 | 作用 | 复用来源 |
|---|---|---|
| `live_contacts` | 全量联系人/群，含类型、备注、别名、好友标记、群人数；另供群成员列表 | WeFlow `engine/contacts.py` 的查询口径 |
| `live_sns_timeline` | 朋友圈时间线：作者、正文、媒体、点赞、评论、时间 | **直接移植** WeFlow `engine/sns.py` 的 XML 解析 |
| `live_sns_annual` | 朋友圈年度统计 | WeFlow `engine/sns.py:_all_posts` + 年度聚合 |
| `live_media_index` | 按时间列出本机已落盘的图片/视频（md5、大小、时间、所属会话） | WeFlow `engine/media.py` 的硬链解析 |
| `live_stats` | 聊天分析聚合（总览、Top 联系人、24h/周分布、类型占比、我的每日发送）；`scope=group` 时出群聊视角 | WeFlow `engine/reports.py:_scan_aggregate` |
| `live_reports` | 可用年份、年度报告、双人报告 | WeFlow `engine/reports.py` 的 `*_annual*` / `_dual_scan` |
| `live_footprint` | 我参与的私聊往来 + 群聊被 @ 的时刻时间线 | WeFlow `engine/reports.py:_scan_mentions` |

`live_contacts` 同时服务 §5.2 的群成员面板与 §5.5 的 5 类通讯录，不另开工具。

**并复用已接好的 `transcribe_voice`**（见 §3.5）。

朋友圈的 XML 解析**必须移植而非重写**：WeFlow 已处理的是
`SnsTimeLine.content` 的 `TimelineObject/ContentObject/mediaList`，点赞与评论来自
`SnsMessage_tmp3`（`type` 1=赞、2=评论，`feed_id=tid`）。重写只会重犯它踩过的坑。

### 3.3 缓存：`~/.dsh/wechat-local/live-cache/<accountId>/`

| 文件 | 内容 | 失效条件 |
|---|---|---|
| `index.json` | 会话、联系人、消息计数与日期分布 | 账号切换 / `schemaVersion` 变化 / 手动重建 |
| `media.json` | 媒体索引（按时间倒序） | 同上 |
| `sns.json` | 朋友圈（分页，默认最近 500 条） | 同上 |
| `media/<md5>.<ext>` | 已解密的图片/视频本体 | 按 LRU 清理，上限可配 |

- **首次索引**：全量扫，带真实进度（`{phase, done, total}`），不做假转圈。
- **增量**：复用已有的 `poll_new`（2 秒），只更新受影响会话的计数与最近列表，不重跑全量。
- **媒体按需**：只在页面要显示时才解密落盘，不预解。
- **多账号隔离**：按 `accountId` 分目录。`vyra_sidecar` 的 `set_account` 会清缓存，
  门面在每次跨账号调用后把账号切回原值（沿用设置页现有做法）。

### 3.4 HTTP 路由

| 路由 | 用途 |
|---|---|
| `POST /wechat-live.rpc` | 页面所有数据请求（`{op, args}` → `{ok, data}` / `{ok:false, error, error_code, suggestion}`） |
| `GET /wechat-live/avatar?account=&talker=` | 头像（已有，`AVATAR_PATH` 复用） |
| `GET /wechat-live/media?account=&md5=&kind=image|video|thumb` | 媒体字节 |

媒体路由：
- 命中磁盘缓存直接返回；未命中→调侧车解密→落盘→返回；
- 带 `ETag` 与 `cache-control: private, max-age=86400`；
- **支持 Range**（拖动进度条）；不支持 Range 的长视频在页面标注「长视频加载可能较慢」。

### 3.5 语音转写

`wechat_asr.py` 代码完整存在（模型自动下载、`pilk` 解 SILK、sherpa-onnx Paraformer）。
`sidecar.py` 把 `transcribe_voice` 放进了 `_UNAVAILABLE_TOOLS`，但**本插件早已绕过**：

- `lib/runtime.js` 的 uv 参数已含 `--with pilk --with sherpa-onnx --with numpy`；
- `vyra_sidecar.py` 已把 `transcribe_voice` 重新挂回 `DISPATCH`，并纳入 `_ACCOUNT_SCOPED`；
- `vyra_voice.py` 提供 `wechat_voice_model {action: 'status'|'download'}`，在后台线程下载模型，
  不阻塞侧车请求循环。

所以 Live 要做的是**接线，不是重造**：

1. 页面调 `wechat_voice_model {action:'status'}` 判断模型是否就绪；
2. 未就绪则 `{action:'download'}` 并在页面轮询 `status` 显示下载进度（约 82MB）；
3. 就绪后调 `transcribe_voice` 取文字。

`transcribe_voice` 仍**不进 Agent 白名单**（`lib/tools.js` 不变），只给页面与监听批次使用。

## 4. 统计口径（`lib/live/stats.js`，纯函数）

三个页面（聊天分析、年度报告、我的足迹）共用一套聚合。**口径写死在代码里并有单测**，
否则三个页面的数字会互相打架。

| 规则 | 定义 |
|---|---|
| 一条消息 | 以 `talker + localId` 唯一 |
| 「我发的」 | `from_me === true` |
| 群里的「ta」 | 用消息的 `sender`；空则归入「未知成员」，**不并到群本身** |
| 系统消息 | 计入「系统」类型与总条数，但不计入「我发/ta发」 |
| 年份归属 | 按 `Asia/Shanghai` 本地时区的年 |
| 活跃时段 | 按小时桶（0–23） |
| 连续天数 | 按本地日期去重后求最长连续 |
| 被 @ | 复用侧车 `at_me_in_source(content, me)`，与私聊判定同源 |

## 5. 页面规格

每页写：**WeFlow 有 → Live 怎么做 → 数据来源 → 取舍**。
凡标「照搬」的，交互、空态、错误文案都以 WeFlow 现有实现为准。

### 5.1 用户画像（`/profile`）

**WeFlow 有**：画像清单（带搜索、按当前账号会话表过滤、显示真实名称而非 wxid）→
选中一份 → Markdown 编辑器 → 保存 / 删除；「生成」与「批量生成」→ 预览 → 保存或丢弃。

**Live**：
- 清单、编辑器、预览、删除**照搬**；清单数据来自 `wechat_profile_get` / `profile_list`，头像走头像路由。
- 「生成 / 批量生成」**改走 DSH 会话**：勾选 N 个对象 → 新建一个 PC微信 workspace 会话 →
  Agent 调 `wechat_digest` → 写 Markdown → `wechat_profile_save` → `wechat_distill_state` 记水位。
  页面订阅该会话的进展（会话日志是事实来源），显示逐个进度。
- 生成是长任务，**关掉页面不丢**：进度在会话里，回来继续看。

**数据**：`wechat_profile_get/list/save/clear`、`wechat_digest`、`wechat_distill_state`（后三个经 DSH 会话）。

**取舍**：不再要求配置 API Key（WeFlow 依赖 `aiModelApiKey`）；模型跟随 DSH。

---

### 5.2 聊天（`/chat`）

**WeFlow 有**：左侧会话列表（未读、预览、置顶、搜索、类型筛选）+ 右侧消息流
（全部消息类型、连续消息合并、时间分隔）+ 搜索与跳日期 + 图片预览 + 语音转写 +
群成员面板 + AI 群聊总结 + 发送 + 修改本地消息。

**Live**：

| 模块 | 做法 | 数据 |
|---|---|---|
| 会话列表 | 照搬；未读、最后一条预览、搜索、类型筛选 | `list_sessions` / `list_unread` |
| 消息流 | 照搬全类型渲染。非文本消息用侧车 `describe_nontext` 的结果，不自己解析 XML | `read_history`（`before_ts` 翻页） |
| 会话内搜索 / 跨会话搜索 | 照搬，命中处高亮并可滚到该条 | `search_messages` |
| 跳日期 | 照抄 WeFlow 的 `JumpToDateDialog`/`Popover` 交互（日历选日→滚到那天） | `read_history` |
| 图片/视频 | 网格 + 大图预览（缩放、上一张/下一张、下载）；Live Photo 打角标 | 媒体路由 |
| **语音转写** | 语音显示「[语音 3″]」+「转文字」按钮；首次触发模型下载并显示进度 | `transcribe_voice`（§3.5） |
| 群成员 | 群聊头部显示成员数，点开成员列表（头像、群昵称、是否好友） | `live_contacts` 的群成员部分 |
| **AI 群聊总结** | 选中一个群 →「总结」→ 走 DSH 会话（取最近 N 条 → 让 Agent 总结 → 结果贴在面板上，可保存为笔记） | DSH 会话 |
| 发送 | 输入框 + 表情 + 文件；**默认 `dry_run` 预览**，真发前二次确认（会抢前台） | `send_text` / `send_file` |
| 修改本地消息 | **不做** | — |

**取舍**：WeFlow 的消息类型渲染有 500KB 级实现，Live 只保证「与侧车 `describe_nontext`
一致」这一层，不追平它的每个视觉细节。

---

### 5.3 AI Agent（`/ai`）

**WeFlow 有**：对话页（消息流、思考链、工具调用卡片、进度面板、推理强度、token 用量、
历史记录、@联系人限定范围、深度研究模式）。

**Live**：**页面是 DSH 会话的前端**（用户已选定）。

- 左侧：PC微信 workspace 下的会话列表（新建 / 切换 / 归档）。
- 中间：消息流 + 输入框。**渲染、流式、工具卡片、思考链、审批、压缩、用量全部用 DSH 自己的**。
- 保留 WeFlow 有价值的部分：**数据范围选择器**——「全部 / 某个会话 / 时间范围 / 含朋友圈」，
  选中后在首条消息里以结构化文本注入，告诉 Agent 这次要读哪一段。
- **不做**内嵌一套独立消息渲染器（避免两套真相）。

**取舍（重要）**：WeFlow 的 Agent 自己跑工具循环（`agentModelLedService` 574KB）；
Live 的 Agent 用 DSH 的工具与权限体系，能力更强（能读文件、跑命令、搜网页），
但**不再有 WeFlow 特有的「深度研究」编排**——用 DSH 的 plan / 子代理替代。

---

### 5.4 朋友圈（`/sns`）

**WeFlow 有**：时间线（作者、正文含表情与链接、图片九宫格 1/2/3/4/9 布局、视频、点赞、评论）+
筛选（时间、作者、有图/有视频、关键词）+ 联系人专属时间线 + 年度统计 + **导出朋友圈**。

**Live**：全部照搬，包括：

- 列表与筛选：`SnsPostItem` 的布局规则、`SnsFilterPanel` 的条件、`ContactSnsTimelineDialog` 的跳转；
- **导出对话框照搬**：格式选择、媒体勾选（图片/视频/实况）、范围（全部 / 所选联系人）、
  同步主页面关键词、导出结果（条数与媒体数）、失败原因；
- 媒体：CDN 原图优先，失败回落本地缩略图，**明确标注「本机缓存」**而不是显示破图。

**数据**：`live_sns_timeline`、`live_sns_annual`、`live_contacts`、媒体路由。
导出在 Host 侧落盘（WeFlow 的导出引擎是 `welive.exe`，Live 用 Node 写文件）。

**限制（必须在页面写明）**：只读本机数据库里已有的朋友圈；微信没同步的、别人删掉的看不到；
图片是加密 CDN 链接，离线或过期时只有缩略图。

---

### 5.5 通讯录（`/contacts`）

**WeFlow 有**：按 **5 类**筛选——好友 / 群聊 / 公众号 / 曾经的好友 / 黑名单；
字母索引分组；搜索；每行头像 + 备注/昵称/别名；点击进详情（看 TA 的朋友圈时间线、看聊天记录）；
群成员列表；**批量导出联系人**。

**Live**：照搬全部 5 类与批量导出。另外：

- 每个联系人行右侧显示**当前回复策略档位**（直接代回 / 起草给我确认 / 只提醒我 / 黑名单），
  点击可直接改——把 WeFlow 放设置里的「自动回复名单」搬到使用现场。
- 联系人详情里的「看朋友圈」直接打开 5.4 的筛选态；「看聊天」跳 5.2 并选中该会话。

**数据**：`live_contacts`、`autoreply_rules`（策略读写）、头像路由。

---

### 5.6 资源浏览（`/resources`）

**WeFlow 有**：展示**本机已落盘的图片/视频**，**按时间流**（默认「今天」），时间范围可选
（今天 / 近 7 天 / 近 30 天 / 自定义）；信息浮层、**删除资源**、**更新画质**；
没有下载过的媒体取不到。

**Live**：**照 WeFlow 的时间流逻辑**（不按会话聚合）。

- 网格 + 时间分组；范围切换即时生效；
- 每项：信息浮层（会话、时间、大小、md5）、跳到原会话、「更新画质」（重新解密原图）、删除缓存；
- 空态必须区分三件事：**「今天没有」**（提示改范围，这是 WeFlow 最常见的困惑）、
  **「图片密钥未就绪」**（给 §6 的引导）、**「真的没有媒体」**。

**数据**：`live_media_index`、媒体路由。

### 5.7 聊天分析（`/analytics`）

**WeFlow 有**：**欢迎页**（「加载缓存」= 上次结果 + 更新时间 / 「新的分析」= 重扫）→
私聊分析（总览、Top 20 联系人、24 小时分布、周分布、我的每日发送曲线、**排除名单**）→
群聊分析（独立视角：群清单、成员发言排行、活跃时段、媒体统计）。

**Live**：照搬，含三件容易漏的：

- **欢迎页**：先给「上次分析于 X」和两个按钮，而不是直接开扫；
- **结果缓存**：分析结果落盘，重开页面直接显示，不重算；
- **排除名单**：可增删、可反选、可重置——这是让数字可信的关键功能。

图表自绘 SVG 折线/柱状/环形，不引图表库。

**数据**：`live_stats`（私聊）、群聊聚合（`live_stats` 的群模式）。

### 5.8 年度报告（`/annual-report`）

**WeFlow 有**：年份选择（**渐进加载 + 策略切换 + 超时回退**）、「全部时间」、总年度报告、
**双人年度报告**（选一位好友只看私聊）、报告窗口（热力图 `ReportHeatmap`、词云
`ReportWordCloud`）、报告导出。

**Live**：照搬。

- 年份列表按 WeFlow 的渐进策略：先出已缓存的年份，再后台补全，超时降级为「只列已知年份」；
- 报告内容：总报告（消息量、活跃时段、关键词、最长连续、最密集的一天、首次/最近联系）与
  双人报告（双方消息量、时间对比、共同词、最长连续对话）；
- 热力图与词云自绘；
- 报告在 DSH 里以**全屏覆盖层**呈现（WeFlow 是独立窗口，DSH 不开新窗口）：
  挂到 `shell.overlay` 的 `LiveTheater`，`Esc` 关闭，关闭后回到年度报告页原位置；
- 报告导出：长图（Canvas → PNG）与纯文本，落 `~/Documents/微信 Live/`。

**数据**：`live_reports`。

### 5.9 我的足迹（`/footprint`）

**WeFlow 有**：范围预设（今天 / 昨天 / 本周 / 上周 / 最近 7 天 / 30 天 / 自定义）、
私聊往来与**群聊里被 @** 的时间线、`@我` 高亮、按会话分组、时长标签、`[空消息]` 占位。

**Live**：照搬，含内容清洗（HTML 实体解码、去掉群消息的发送者前缀、`@我` 分词高亮）。

**数据**：`live_footprint`。

### 5.10 导出（`/export`）

**WeFlow 有**：会话表格（多选 / 全选）、导出配置（格式、时间范围、是否含媒体、目录结构）、
任务中心（进度 / 取消）、导出记录与「再导一次」、**9 种格式**（JSON / HTML / Markdown / TXT /
Excel / CSV / PGSQL / ChatLab / WeClone）、网页版导出、自动化任务。

**Live**：
- 会话选择与配置界面**照搬**；
- **格式第一期只做侧车已有的 5 种**：md / html / json / csv / pdf（用户已确认够用）。
  Excel / SQL / ChatLab / WeClone / 网页版列入第二期，界面上标注「暂不支持」而不是隐藏选项；
- 任务中心：异步任务、真实进度、取消、打开所在文件夹；
- 导出记录（谁、何时、多少条、多大、路径）与「再导一次」；
- **不做**自动化定时导出。

**数据**：`preview_export`（规模预览）、`export_chat`（侧车）。

**产物结构**（照 WeFlow）：
```
<导出目录>/<会话名>/
├── chat.<格式>
├── assets/      # 图片
└── files/       # 文件附件
```

### 5.11 数据库备份（`/backup`）

**WeFlow 有**：创建备份（可选含图片/视频/文件）、选择备份、载入、进度百分比、
清单摘要（来源账号、版本、资源、新增/已存在/跳过）、「Snapshots 增量备份」定位。

**Live**：交互照搬，**对象是 Live 自己的数据**：
- 创建：把 `live-cache/<accountId>/` 的索引与（可选）媒体打成一个归档
  （`.tar.gz`，含媒体时 `.tar`），写清单 `manifest.json`；
- 载入：读清单 → 校验 `schemaVersion` → 重建索引 → 报告「新增 / 已存在 / 跳过」；
- 页面明确写：**这是微信 Live 的数据快照，不是微信数据库的恢复源**（不假装能还原微信数据）；
- 进度条显示实际打包字节数。

**数据**：`lib/live/backup.js`（Node 侧）。

## 6. 初始化与「PC微信」设置页

### 6.1 图片密钥（可跳过）

WeFlow 的原文案与四种状态**照搬**（`WelcomePage.describeImageKeyFailure`）：

| 状态 | 文案 |
|---|---|
| `cache_stale` | 缓存的图片密钥已失效：在微信里打开一张图片后点「内存扫描」 |
| `need_open_image` | 内存里暂时没有图片密钥：打开一张图片后再试 |
| `unsupported` | 缺少图片解密依赖，可先跳过，稍后在设置里重试 |
| 其它失败 | 显示侧车返回的 `suggestion`，没有则显示 `error` |

关键前提（页面上要写）：微信只有**刚查看过图片**时才把图片 AES Key 放进内存。
图片密钥是**账号级**的，换号后旧密钥解不了新号的图。

未就绪时，聊天/朋友圈/资源浏览的图片位置显示明确原因，**不显示破图**。

### 6.2 「PC微信」设置页（精简）

现有三个页签中，与 Live 重复的能力搬走后，设置页只保留**控制与初始化**：

| 页签 | 内容 |
|---|---|
| **Live 设置** | `sidebar`（是否在左侧菜单显示微信 Live）、`notify`（是否启用系统通知）、默认打开页、媒体缓存上限 |
| **回复策略** | **保留**（WeFlow 的自动回复名单；通讯录里也能改，两处同一份 `rules.json`） |
| **账号与状态** | 账号列表与切换（右上角账号菜单的完整版）、侧车版本/运行方式、环境自检（数据目录 / 微信 / 依赖 / 版本 / 账号）、重新检测、一键修复、已注册工具清单、图片密钥状态与「内存扫描」 |
| **画像蒸馏** | **移出到 Live 的「用户画像」页**（原设置页入口保留一个跳转链接） |

## 8. 错误与空态契约（横切）

| 场景 | 表现 |
|---|---|
| 微信未运行 / 密钥取不到 | 顶部红色状态带 + 全页可操作提示；不显示空列表 |
| 侧车返回错误 | 原样显示 `error_code` + `suggestion`（`env_not_ready` / `target_not_found` / `bad_args` / `not_archived` / `internal_error`），不吞成空结果 |
| 尚未索引 | 骨架 + 「首次索引中 · 42%」真实进度 |
| 索引完成但无数据 | 分三类文案：微信里没有 / 时间范围内没有 / 图片密钥未就绪 |
| 媒体解密失败 | 该项显示失败角标与原因，列表继续可用 |

## 11. 风险

| 风险 | 应对 |
|---|---|
| 首次索引慢（大库可能数十秒） | 真实进度 + 后台任务 + 结果落盘；超时降级为「先出会话，计数后补」 |
| 图片密钥拿不到（微信未在图已打开状态） | 照 WeFlow 的四种状态给可操作文案；不阻塞其它功能 |
| `sherpa-onnx` 首次安装约 80MB + 模型 82MB | 明确提示体积与进度；失败可重试；不影响其它页面 |
| 朋友圈解析依赖微信内部 XML 格式 | 移植 WeFlow 的解析并保留其容错；解析失败记为「无法解析」而不是空帖 |
| AI Agent 与 DSH 原生对话两套入口 | Live 只做「范围选择 + 会话列表」，渲染与执行全在 DSH，不做第二套消息渲染器 |
| 侧车是快照（lumii 更新后不同步） | `vyra_live.py` 只依赖 `wechat_core` 的既有私有函数，升级时按此清单核对 |
