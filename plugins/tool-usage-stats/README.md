# dsh-vyra-tool-usage-stats · 工具分析

**看工具到底在用没用、错在哪，然后把证据丢给模型去改。**

```sh
dsh plugin --profile web add dsh-vyra-tool-usage-stats
```


## 它做什么

统计每次工具调用，**记下每次失败的原因**。面板按工具排行，勾选出有问题的几个，一键把它们的统计与失败样本连同分析提示词复制走——粘进对话，模型就能找出反复出错的那个并给你修复。

- **排行**：每个工具被调多少次、失败多少次、失败率、最后使用时间
- **失败原因**：展开某一行的失败数，看最近几次失败的时间、错误码、错误摘要
- **多选复制**：勾选工具 → 「复制错误日志」→ 粘进对话输入框
- **5 档统计范围**：所有 / 最近 30 天 / 最近 7 天 / 最近 3 天 / 今天
- **导出 JSON**：把全部统计与失败记录下载下来，可以拿到别处聚合

## 为什么是「复制」而不是插件自己去问模型

早期版本会定时自己把失败交给 Agent 诊断，再让你点「应用」。那条路要凑齐三样东西才能跑：一个活着的会话、一个配好的模型、以及一组「什么时候值得问」的阈值（新增失败几次、隔几天）。

**现在直接把这堆文本给你。** 你本来就在对话里，模型有上下文，也不用再维护那三个数字。

## 用法

设置 → **工具分析**。

1. 上面选**统计范围**
2. 下面**勾选**你想查的工具（或点「全选」）
3. 点**「复制错误日志」**
4. 粘进对话输入框

复制出来的内容长这样：

```
请分析下面这些工具调用失败，找出反复出错的原因，并给出具体的修复建议。

统计范围：最近 7 天

## bash
调用 42 次，失败 7 次（16.7%），最后使用 11-18 14:20
最近的失败：
- 11-18 14:19 [BASH_FAILED] command exited with code 1
- 11-18 13:02 [TIMEOUT] command timed out after 30s
```

## 数据从哪来

订阅 `session/event`，折叠日志里**本来就有**的 `tool/call` 与 `tool/result` 记录——不另开一条采集通道，所以统计结果不会和实际执行对不上。

失败原因有两个来源，缺一不可：工具**返回**失败时取模型可见的内容，工具**抛出**异常时取事件的 error 成员。只看一路的话，整类失败会没有原因可查。

## 数据保留

| 项 | 默认 | 说明 |
|---|---|---|
| 按日分桶 | 90 天 | 更早的日桶丢弃；**累计计数永不裁剪**（累计回答的是"这工具到底用过没有"） |
| 失败样本 | 每个工具 20 条 | 保留最新的，供展开查看与复制 |

两个都在插件配置里改：

```yaml
- id: tool-usage-stats
  config:
    retainDays: 90
    retainFailures: 20
```

## 边界

- **它不调用模型、不改工具、不拦截调用**。只统计，然后把文本给你
- 统计数据是本地派生的，某个记录读不出来会跳过备份，不会让插件加载失败
- 「今天」按本地日期分桶，不是滚动 24 小时

## 安装

在客户端「设置 → 插件 → 索引源」加入：

```
https://lanxiake.github.io/dsh-vyra-plugins/index.json
```

然后搜索「工具分析」安装。

## 开发

```sh
node scripts/build.mjs            # src/ → lib/
npx tsx tests/check.ts            # 全部检查（需要同级 dsh-Veyra checkout）
```

`check.ts` 跑单测，再从 `dsh-Veyra` checkout 里跑四个 harness 检查：HTTP 端点、存储校验、会话端到端、以及**启动定时器存活**（后者存在的理由见 `tests/boot-timers.ts` 顶部注释——曾有一个定时器调用已被删除的函数，宿主在启动 15 秒后崩溃，而所有同步检查都是通过的）。
