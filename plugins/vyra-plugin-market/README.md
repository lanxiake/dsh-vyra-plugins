# vyra-plugin-market · 插件市场

**在插件页里多一个标签页，卡片式逛市场。** 位置就在「已安装」旁边。

## 它解决什么问题

DSH 自带的 Discover 是一次一个市场源、一次装一个；社区市场插件（`dsh-plugin`）又另建了一套安装通道。

这个插件把**浏览**和**批量操作**合到一起：

- **多市场源**：在下拉里切换，源列表与「设置 → 插件 → 索引源」是同一份配置，两处看到的一样；没有配源时自动加入 Veyra 插件源
- **卡片式预览**：图标、名称、包名、简介、版本、作者、发布时间、状态标签（已安装 / 可更新 / 客户端自带 / 版本不兼容 / 预览版）
- **搜索与筛选**：全文搜索（跨中英文字段）、分类胶囊、默认 / 相关度 / 发布时间排序、分页
- **批量操作**：勾选后一次**安装 / 更新、卸载、启用、停用**多个插件，操作前弹确认框逐条列出目标
- **后台执行、随时中断**：安装 / 更新不绑在页面上，切到别的页面也照常进行；进度条上的「取消」会停掉剩下的条目（正在宿主机上的那一个会跑完，pnpm/git 无法中途终止）

## 用法

打开「设置 → 插件」（或侧栏的插件面板），切到「插件市场」标签页。

勾选若干卡片后，上方出现批量条；「安装 / 更新」与「卸载」会先弹确认框列出将要改动的每一项。

## 它凭什么能装插件

**它不自己装插件。** 所有读取与改动都走客户端自己的 Remote 接口：

| 做什么 | 走哪条 |
|---|---|
| 读市场源、搜索、分页 | `remote.pluginMarket` |
| 安装、更新、卸载、启用、停用 | `remote.pluginManager` |

因此：

- **索引源配置只有一份**。这里切源改的就是「设置 → 插件 → 索引源」，不是另存一份
- **安装结果与官方一致**。走的是同一个插件管理器，同一个 profile 锁，同一条 pnpm 通道
- **不新增网络通道**。索引由宿主拉取解析（所以索引源即使没开 CORS 也能读），本插件不直连

## 边界

- **索引是第三方内容**：标题、图标、安装来源都由索引自己声明，客户端只校验格式。只添加你信任的源
- **更新只对 Git 安装的插件生效**：`updateBundle` 只接受宿主标记 `update: true` 的版本（即同一仓库目录的另一个提交）；npm 装的插件在客户端里没有原地升级的通道，需要先卸载再安装
- **客户端自带（provided）的插件不会出现在卸载按钮上**——它不是这个 profile 装的，不该由这里删

## 安装

在客户端「设置 → 插件 → 索引源」加入：

```
https://lanxiake.github.io/dsh-vyra-plugins/index.json
```

然后搜索「插件市场」安装。

## 为什么没有宿主端

索引获取、解析、搜索、分页、安装状态标注都在宿主侧的 `pluginMarket` 里，插件改动也在 `pluginManager` 里——客户端插件只要能调这两个 Remote 就够了，不需要自己的服务端路由、缓存或存储。所以 `index.js` 是一个空的挂载行，只为让客户端半被加载。

## 开发

```sh
pnpm run test:market        # 纯逻辑自检 + 用桩 React/Remote 渲染一遍
```

`test.mjs` 覆盖卡片状态、批量计划、安装/更新分派这些纯决策；`render-check.mjs` 用桩把标签页真正渲染一次，验证注册进 `plugins.tab`、空源时自动加源、卡片的 Install 走 `installBundle`。
