# 旁白格式 v1（learning-coach 写，引擎只读）

> 旁白是音频 / 视频的**第二内容源**。它不是课件的复制品：课件写给眼睛，旁白写给耳朵。
> 规则只有一条主线：**按课件的 `##` 小节逐字对齐**；对不上就报错，不静默错位。

## 1. 文件位置与命名

```
<科目>/lessons/<序号>-<节点id>.narration.md
```

与课件同名、同序号，只多 `.narration.md` 后缀。例如：

```
lessons/0001-intro.why-content-works.md
lessons/0001-intro.why-content-works.quiz.json
lessons/0001-intro.why-content-works.narration.md   ← 旁白
```

一份旁白对应**一节课**；不做跨课合并。

## 2. front matter（可选）

```markdown
---
title: 一条内容为什么会被看完
instruction: professional teacher explaining clearly and patiently, moderate pace, warm and conversational
---
```

- 允许 `title` 与 `instruction`。
- `title` 写了就必须与课件 front matter 的 `title` 逐字一致。
- `instruction` 是全课默认语气（Breeze 用；自然语言，英文效果更好）。分节 `@instruction` 覆盖它。
- 省略 front matter 也能用。

## 3. 小节

```markdown
## 一条内容要过的三关

（这一节的口播）

## 第一关：被点开

（这一节的口播）
```

- 只允许 `##`；`#`、`###` 及以下都报错。
- 每个 `##` 标题必须与课件里的某个 `##` 标题**逐字一致**，顺序也要一致。
- **可以少写**：某节没写旁白，引擎退回自动抽取的旁白；不会因此阻断。
- **不能多写**：课件里没有的标题、重复标题、顺序颠倒都报错。

### 分节语气（Breeze）

在 `##` 标题的下一行写 `@instruction:`，描述这一节想怎么讲：

```markdown
## 第一关：被点开
@instruction: clear and explanatory, emphasizing the key contrast, moderate pace

刷首页的人不是在阅读，是在扫。……
```

规则：

- 必须紧跟在 `##` 标题下面，写在正文之前；一节只能一条。
- 自然语言描述，英文效果更好；它**不会被朗读**，也不会进文字稿。
- 分节指令覆盖 front matter 的全局 `instruction`。
- edge / native 会忽略它；Breeze 会把它传给模型。
- 认不出 `@` 指令、重复、顺序不对都会报错。

推荐语气库：

| 场景 | instruction |
|---|---|
| 冷开场 | `curious and engaging, opening a conversation, slightly brisk` |
| 讲解 | `professional teacher explaining clearly and patiently, moderate pace` |
| 对比 / 强调 | `clear and explanatory, emphasizing the key contrast` |
| 案例 / 故事 | `warm storyteller, conversational, a little surprised` |
| 边界 / 警告 | `serious but reassuring, emphasizing trust and small steps` |
| 小结 | `encouraging and confident, summarizing and pointing forward` |

Breeze 还支持 `[笑]`、`[叹气]`、`[清嗓子]` 等语音事件，以及克隆参考音频。它们属于 **Breeze 专属**：edge / native 会把方括号内容当普通文字读出来，所以默认不要写；确实需要时，只在 Breeze 专用稿里用。

## 4. 正文

- 只写**口头要讲的话**：普通段落，空行分段。
- 不写：代码围栏、表格、`:::` 指令块、HTML 标签、图片。
- 行内标记（反引号、`**`、链接、公式）允许写，但引擎会在朗读前剥掉标记；公式统一读作「公式」。
- 代码与公式**不逐字朗读**：课件里的代码块在音频里只说「看这段代码」，画面由视频负责。

## 5. 与题目的关系

引擎会在有小节含 `::: quiz` 锚点时，自动在该节旁白末尾补一句：

> 这一节有一道题，回到阅读端做一下。

所以**旁白里不要自己写题目提示**，也不要抄题目正文。题只归 `practice-evaluator`。

## 6. 兜底与失败

| 情况 | 行为 |
|---|---|
| 没有 `narration.md` | 用自动抽取的旁白（段落 / 列表 / 图注 / 练习标题） |
| 某节没写 | 该节用自动旁白，其余照用 |
| 标题对不上 / 顺序错 / 多写标题 | 校验报错，媒体生成不启动 |
| 正文为空 | 该节回退到自动旁白 |
| 课件改了、旁白没改 | 产物标记 stale；重新生成时以新课件为准 |

## 7. 示例

```markdown
---
title: 一条内容为什么会被看完
---

## 一条内容要过的三关

先别急着讲你的产品。想象一个读者，手指正在往上划：他停下来，通常不是因为你写得全，而是因为他认出了自己的处境。
这一节我们只做一件事：把「被点开、被读完、被照着做」这三关分开，看看每一关各在修什么。

## 第一关：被点开

刷首页的人不是在阅读，是在扫。要让他的手指停一下，需要两件事同时成立：注意力有限，以及一个刚好够大的信息缺口。
缺口太小，他觉得答案不值钱；缺口太大，他觉得跟自己无关。中间那一段才好用。
```

## 9. 纯音频的额外规则（2026-11-22）

音频用户没有文字和图片，规则比“读起来顺”更严。完整依据见 [纯音频课件：理论、证据与讲解方法](../设计/纯音频课件-理论与方法.md)。

**必须**

- 每节只讲一个主要观点；估算超过 4 分钟就拆节。
- 禁止视觉指代：`如图` / `上表` / `左边` / `这个按钮` / `看这段代码`。要描述，不要指。
- 不写代码围栏、表格、公式原文；公式用自然语言读，代码讲意图。
- 术语首次出现要定义；同一术语全课一致。
- 每节最后一句是这一节的小结。
- 需要动手的地方明确说“暂停，去阅读端/编辑器做”。

**建议**

- 单句 ≤ 30 个汉字；长句拆开。
- 多用第二人称、主动语态、具体例子。
- 每 3–5 分钟一个小回顾；章末 1–2 个问题，答案前留 3–5 秒。
- 开头给路线图，结尾给“下一步”。

**校验（Phase 1.2 已接入）**

- 视觉指代（如图 / 上表 / 看这段代码）：提醒；narration.md 强制后升级为阻断。
- 空间指代（左边 / 右边 / 表格里）：提醒。
- 代码 / 表格 / HTML：解析层阻断。
- 单句过长（>38 字）、单节过长（>4 分钟）、无小结：提醒。
- 术语一致性：对照 GLOSSARY（P1）。

**audio_fit（建议字段）**

```yaml
audio_fit: high | medium | low
audio_note: "代码部分要回到阅读端实操"
```

- `high`：完整音频；
- `medium`：音频 + 视觉提示；
- `low`：只做概念音频，或跳过。

## 10. 生成音频（Phase 1.2）

```bash
# 生成整课（默认 1.2×，晓晓音色）
npm run media:audio -- \
  --workspace <学习工作区> \
  --subject <科目 slug> \
  --node <节点 id> \
  --all \
  --narration <临时 narration.md> \
  --root <媒体缓存目录>

# 只生成前两场试听
npm run media:audio -- ... --scene 1,2
```

产物目录里会有 `lesson.mp3`、`transcript.md`、`chapters.json`、`player.html`、`manifest.json`。`player.html` 是离线播放器：章节、相对倍速、倒退 15 秒、续听、文字稿链接。

音频已按 `--rate`（默认 `+20%`）生成；播放器里的倍速是**相对倍速**，默认 1.0×。

**本地 provider**

```bash
# 系统语音兜底（Windows SAPI / macOS say / Linux espeak-ng）
npm run media:audio -- ... --provider native

# Breeze 本地模型：先启动 FastAPI 服务（首次加载约 4 分钟）
cd E:/ai/breeze-tts
E:/ai/breeze-tts/.venv/Scripts/python.exe -m breeze_infer.api E:/ai/breeze-tts-2 --host 127.0.0.1 --port 7860

# 若 7860 被拒绝（WinError 10013），换 7861：
#   ... --port 7861
#   生成时加 --breeze-api http://127.0.0.1:7861

# 另开一个终端生成（自然语速；非商业许可）
npm run media:audio -- ... --provider breeze \
  --breeze-api http://127.0.0.1:7860 \
  --breeze-instruction "professional teacher explaining clearly and patiently"
```

`narration.md` 里的 `instruction` / `@instruction:` 会覆盖 `--breeze-instruction` 的全局默认；这样同一节课可以冷开场好奇、定义平静、案例温暖、小结鼓励。

- native 输出 WAV 或 MP3 由 ffmpeg 拼接；单场是 WAV，音质一般但完全离线。
- Breeze 使用自然语速；需要 1.2× 时在播放器里调相对倍速。
- 克隆模式加 `--breeze-ref-audio <文件> --breeze-ref-text <逐字稿>`；必须取得本人同意。
