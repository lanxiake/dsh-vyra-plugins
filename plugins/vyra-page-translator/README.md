# vyra-page-translator · 整页翻译

**像浏览器那样翻译整个页面**——不是把 DOM 整个塞给模型，而是按段落切分、批量提交、把译文替换回去，原有的排版、链接、行内样式都不动。

## 它解决什么问题

网页翻译的难点不在"翻译"，在**结构**：一个页面里混着导航、正文、代码块、按钮文案和时间戳，整块送进模型既贵又会丢格式。

这个插件在浏览器端把页面切成可翻译的单元：

| 做法 | 效果 |
|---|---|
| 按 DOM 结构切分，只取文本节点 | 不碰标签，译文回填后排版不变 |
| 按脚本判定语言，跳过已是目标语的部分 | 不重复翻译 |
| 每批 80 段、并发 2 路，滚动时去抖 800ms | 长页面不会一次打爆请求 |
| 译文按节点原位替换 | 链接、加粗、行内代码都保留 |

## 用法

安装后在页面右上角出现翻译按钮，点一下翻译当前页；再点切回原文。语言由 profile 配置决定。

## 面板位置

浮在页面上的按钮 + 展开面板（翻译进度、暂停、切回原文）。

## 网络与隐私

- **只发送页面上的文本**给配置的模型，不发 DOM、不发截图、不发页面 URL 之外的任何东西
- 译文只存在于当前页面内存中，**不落盘**
- 不注入任何远程脚本

## 安装

在客户端「设置 → 插件 → 索引源」加入：

```
https://lanxiake.github.io/dsh-vyra-plugins/index.json
```

然后搜索「整页翻译」安装。

## 已知限制

- 只翻译**当前页面**，不跟随 iframe 跨域内容
- 动态加载的内容需要重新点一次翻译
- 需要模型支持较长的批量输入；上下文窗口小的模型建议调小批大小

## 开发

插件由宿主端（`index.js`，注册路由与配置）和浏览器端（`client.js`，DOM 适配与面板）两半组成，切分逻辑在 `translate-core.js`。
